# 💡 将来的な追加アイデア

[READMEへ戻る](../README.md) · [English](en/roadmap.md)

第2弾で入れたもの、第3弾の案、その先の案、将来案に入れないものをまとめます。

## 第2弾で入れたもの

> 可聴域の上端（18〜22kHz）を、途切れのない記録として残す。  
> その帯域の値を、本体のdBFSと同じ区間・同じ行に、閾値に関係なく1行ずつ残す。

第1弾で作ったのは「区間を落とさずに記録する」ところまでです。第2弾では、その記録に可聴域の上端（18〜22kHz）の帯域を足しました。多くの大人には聞き取りにくい帯域ですが、若い人には聞こえることがあるので、「聞こえない帯域」とは呼びません。第2弾で入れたのは、CSVの帯域の3列（[CSVの資料](csv.md)の「帯域の列」）と、画面の超音波帯の破線・統計の「超音波帯の最大」・超音波帯の現在値・記録できる上限の表示です。

近い既存のツールとの違いは次のとおりです。2026-09-29に、ブラウザーで動く既存のツールをコードまで読んで調べた範囲の話で、ほかに無いことの証明ではありません。

| 観点 | 既存のツール | 本ツール（第2弾） |
|---|---|---|
| 18kHz超の扱い | frequencydetector.com の Ultrasonic Spectrum Analyzer・noisemeter.co の Spectrum Analyzer など、ナイキスト周波数（サンプルレートの半分）まで表示するものがある | 同じ帯域を扱う |
| 時系列の記録とCSV | frequencydetector.com の Ultrasonic Leak Detector は、17〜22kHzの帯域エネルギーを時刻つきでCSVに出す（第2弾にいちばん近い）。ただし閾値を超えたときだけ記録し、最大60行で古い行から消え、時刻に日付がなく、タブが隠れると止まる | 閾値に関係なく、区間ごとに1行ずつ、長時間残す |
| 欠けた区間 | noisemeter.co の Overnight Noise Monitor は、値の来ない秒に行を作らないので、欠落と区別できない | 欠けた区間も行として残し、サンプル数（`valid_ratio`）で連続性を確かめられる |
| 外部への送信 | `connect-src 'none'`で送信を止めているものは見つからなかった | `connect-src 'none'`で、fetch・XHR・WebSocket・sendBeaconを止めている |
| 音の加工の状態 | jasperbernaers.com の騒音計は、ブラウザーが報告しない項目をunknownとして画面に出す。CSVに残すものは見つからなかった | ブラウザーが報告した状態を、報告しない項目（unknown）も含めてCSVのヘッダーに残す |

⚠**「超音波ビーコンを検出する」とは書きません。**残すのは「この帯域に音のエネルギーがあったか」という記録までです。何の信号なのかという判定は、第3弾の案にも入れていません。帯域のエネルギーだけで信号を見分けるのは難しいと、研究でも指摘されています（SoniControl、arXiv:1807.07617）。

⚠**この記録は証明には使えません。**超音波などによる嫌がらせを「証拠」として残したい、という用途には応えられません。理由は[ユースケースの資料](use-cases.md)の「規制値・基準値とは比較できない」と、[CSVの資料](csv.md)の「ハッシュチェーンで何が分かるか」にあります。

スペクトログラム（何を拾っているかを目で見る表示）は、記録ではないので第3弾へ回しました。

この帯域の値は端末に強く依存します。サンプルレートが44.1kHzなら22.05kHzより上は原理的に表せず、マイクとコーデックの帯域制限でそれより低いところから落ちていることもあります。iPhone 18 Pro Maxの実機では、18〜21kHzのトーンが超音波帯の値で静かなときより+29〜+41dB高く記録され、22kHzは+1.9dBの上がりにとどまりました（[実機テストの資料](real-device-test.md)）。⚠ブラウザーが音の加工を有効にすると、19kHzより上が消えることがあります（Chromiumの疑似マイクで確認）。本ツールは加工を切るよう要求し、実際の状態をCSVのメタ行に残します。サンプルレートも残しているので、あとから確かめられます。

## 第3弾の案

- **スペクトログラム（ファインダー）**  
  何を拾っているかを目で見る表示。記録ではないので、欠けてもよい表示として作る。
- **平時の記録と比べて印を付ける**  
  同じ端末・同じ置き場所で採った平時の記録を基準にし、帯域の値がそれより上がった区間に印を付ける。いまは[CSVの資料](csv.md)のレシピ（`compare.py`で平時の中央値を出し、`over.py`の閾値に渡す）で手作業で行っていることを、画面で行う。何の信号かの判定はしない。
- **探知向けの画面（ピーク保持・方位の交点）**  
  端末を持って歩く・回すときのために、超音波帯の値を大きく出し、ピークを保持する。2地点で取った方位を入れると、交点を示す補助も付ける（[ユースケースの資料](use-cases.md)の「音の方向探知・発信源の絞り込み」）。記録（CSV）はいまのまま残し、画面だけを探知向けにする。
- **AudioContextをマイクのトラックのサンプルレートで作る**  
  マイクの音声トラックとAudioContextのサンプルレートが違うと、変換で上限に近い高い音が下がる（[CSVの資料](csv.md)の「帯域の列」）。AudioContextをトラックのサンプルレートで作り直せば、この変換がなくなる。⚠iOSでは、作り直したAudioContextを利用者の操作の外で再開できないおそれがある。iPhone 18 Pro Maxの実機ではトラックもAudioContextも48000Hzで一致していたので、当面は注意書きで足りると考えている。

## その先の案

- **音量閾値トリガー**  
  設定したdB値を超えるとグラフにマーカーや警告表示を付与。
- **長時間稼働対応**  
  ログをIndexedDB等へ逃がし、タブが落ちても失わない設計（現状はすべてメモリー上にある）。
- **時間重み（Fast／Slow）**  
  音の揺れをならす表示（[計測の資料](measurement.md)の「スムージングの設定を置かない理由」）。Fast=125ms／Slow=1sの時間重みを入れ、表示をこの重みを通した値にする。⚠**記録に追加で載せられるのは区間内のLFmax／LSmaxまでである。**区間のLeqは区間の完全な要約なので、時間重みをかけても区間の平均は変わらない。

## 将来案に入れないもの

次のものは、この先の弾でも入れません。将来案に並べたままにすると、果たされない約束として残るためです。

- **A特性・C特性の重み付け**：重み付けを足してもdBFSはdB SPLにはならない。規制値・基準値と比べるには検定を受けた騒音計が要る（[ユースケースの資料](use-cases.md)の「規制値・基準値とは比較できない」）
- **キャリブレーション（dB SPL推定）**：0 dBFSが何Paに当たるかは、マイクの感度とプリアンプの利得が分からなければ決まらない。どちらもブラウザーからは取れない
- **L10／L50／L90のパーセンタイル、線量計（OSHA・NIOSHのTWA）**：いずれもA特性音圧レベルの分布・累積を前提にした指標である。dBFSの分位点に同じ名前を付けると、規制値と比べられるものだと誤読される
- **ステルスモード**：UIを暗くして画面を目立たなくする案。記録に穴を作らないという本ツールの名乗りと関係がないため入れない
